# 引き継ぎ資料（2026-10-06 時点）

別のAI・別の担当者がこのリポジトリを引き継ぐための現状整理。まず「3. 依頼されている改善」を読み、次に「5. 作業ルール」を守ること。

## 1. これは何か

物語に描かれた戦いを、作中の暦で並べた年表と、各戦いの3D俯瞰再現（部隊の動き・損害・原作/アニメの該当箇所）をまとめた静的サイト。26作品・254の戦い。

- 公開先（本番）: https://fiction-war-archive.birdman-studio.com/ （GitHub Pages、`main` の `/docs`）
- リポジトリ: https://github.com/b-w-hiroki/fiction-war-archive
- 別系統: claude.ai のアーティファクト版（作品一覧と各年表）。URL は `artifacts.json`（`_hub`）と `works/<作品>/artifacts.json`（`_portal`）。今後 claude.ai 版を続けるかは未定。続けないなら無視してよい。
- 作者: Hiroki（個人の副業プロジェクト）。

## 2. 現状の構成

詳細は `README.md` と `CLAUDE.md`（会戦データの書き方）。要点だけ。

| 場所 | 役割 |
| --- | --- |
| `engine/template.html` | 3D再現ページのテンプレート（three.js r128、CDN読込）。陣形・場面送り・倍速・戦果パネル |
| `engine/portal.html` | 年表。全作品を `WORKS` として埋め込み、ページ内で切り替え（URLの `#作品キー`） |
| `engine/hub.html` | 作品一覧（トップ）。作者・媒体・あらすじ付き |
| `engine/common.py` | 恒星・要塞・地形などの環境ヘルパー |
| `works/<作品>/` | `battles/*.py`（1戦い＝1ファイル）、`refs.py`、`impact.py`、`work.json`、`artifacts.json` |
| `site.json` | サイト名、作品の並び、`pages_url`、`domain`、`ga_id`（空） |
| `tools/build.py` | `python3 tools/build.py all` で `docs/` に出力。`--artifact` で `build/artifact/`（claude.ai用） |
| `tools/shot.py` | Playwrightでスマホ幅の撮影。要 `npm i three` 等（/tmp） |
| `docs/` | 公開用の生成物（約17MB）。**手で編集しない。ビルドで再生成する** |

ビルドは Node.js（JS構文検査）と Python 3 が必要。生成物の `docs/` もコミットする運用（Pages が `main/docs` を配信するため）。

### 3.2 色・見た目

- 年表の配色は `engine/portal.html` の CSS 変数と、`tools/build.py` の `PALS`（3D再現用の陣営色）・`COL`（年表用）、`work.json` の `colors` で決まる。
- `allied` と `efsf` は同じ色値。三国志の黄巾の乱で、官軍（allied）と呉（efsf）が同じ青になっている。
- ヴィンランド・サガは戦いごとに陣営色の意味が変わるため、凡例のラベルと合わない戦いがある（例: ロンドン橋で zeon が守備側、フランク砦攻めで lusi が守備側）。
- 氷と炎の歌の紅き婚礼で、フレイ・ボルトン側がラニスターと同じ zeon のため、凡例が「ラニスター側」と表示される。
- 3D再現ページ（`engine/template.html`）の色は暗い背景に高彩度の部隊色で、スマホでの視認性は未検証。見た目の撮影確認をしていない作品がある（新規4作品は構文・読込の検査のみ）。
- ユーザーは過去に「AIっぽさ」「年表の見やすさ」「凡例」「改行位置」にも指摘をしている。方向性: 余計な装飾を避け、事務的で読みやすく。

### 3.3 既知の不具合・注意点

- 起点が無い場面の部隊位置は、エンジンが最初の位置で補う仕様（zipang で null 位置による描画エラーが出たため）。
- `date: 'uc'` の作品は ERA 中の「○○年」から年列を読む。年が無い作品（沈黙の艦隊など）は年列が空になる。
- 作中年が不明な作品は `UC` に並び順用の小数（例 1.01〜1.06）を振っている。

## 5. 作業ルール（ユーザーの方針）

- **原作の文章・台詞は転載しない**。艦艇・紋章・キャラクターは原作デザインを使わず、抽象的な形で表す。
- **数値は資料で確認できたものだけ**載せる。確認できないものは「不明」、記憶にもとづくものは「推定」と明記する。出典はNOTEや refs に残す。
- 結論から短く。褒めない・感情を出さない・事務的に。問題点やリスクは率直に指摘する。
- 長い日本語は BudouX で文節改行される。`work.json` の lead/notes は `span.nb` で改行位置を区切る。
- 会戦データを足すときは `CLAUDE.md` の変数定義に従う。`ENV` の末尾に `specials(...)` を1つ置く。
- 変更は新しいブランチで PR を出し、`python3 tools/build.py all` を通してから `docs/` ごとコミットする。

## 6. 引き継ぎ時の確認コマンド

```sh
python3 tools/build.py all              # 全作品を docs/ へ。エラーなく「26作品」と出ること
python3 tools/build.py all --artifact   # claude.ai 版（任意）
python3 tools/shot.py docs/<作品>/<key>.html 1,3 res 6000   # スマホ幅で撮影し /tmp/cmp.png を見る
```

## 7. 推奨する進め方

1. 全作品のページをスマホ幅で撮影し、色の濃さ・視認性の問題を洗い出す（見た目の基準を先に決める）。
2. 配色を整理する（陣営色の共通パレットを作り、`allied`/`efsf` の重複と凡例ラベルのずれを解消）。
3. 推定・不明の多い作品から、出典を確認して置き換える。確認できない値は「不明」のまま残す。
4. 沈黙の艦隊など定型文の作品に、作品固有の（ただし台詞を引用しない）説明を足す。
5. 抜けている戦いの候補は `notes/candidates.md` を参照。
